# 3つの数字を突き合わせて読み解く

このスキルは、**数字を並べるためのものではありません。**
3つの情報源が必ず食い違うので、**その差が何を意味するかを説明する**のが仕事です。

数字を素朴に比べて「GA4のほうが少ないので計測漏れです」などと言わないでください。
差には理由があり、理由ごとに打つ手が違います。

## 3つの情報源

| | 何を数えているか | 見えないもの |
|---|---|---|
| **ktrackgeo** | 自社サーバーのログ | JSを切っている人（タグ計測のみの場合） |
| **GA4** | タグが発火したセッション | **ボット全般（AIクローラーを含む）**、広告ブロッカー利用者 |
| **Search Console** | Google検索の表示とクリック | Discover・ニュース・広告・他の流入 |

## 差の読み方（ここが本体）

### ① GSCのクリック < ktrackgeo の Google 流入

**差＝Discover・Googleニュース・Google広告・その他のGoogle面。**

Google は参照元として `https://www.google.com/` という**ドメインだけ**を渡してきます
（Referrer-Policy による）。パスも検索語も落ちるため、
**自然検索・Discover・広告の区別は原理的につきません。**

- 「Google検索から◯件」と断定しないこと。正しくは「Google経由で◯件」
- 自然検索だけを知りたい場合は **Search Console の数字が正**
- 差が大きいときは Discover に載っている可能性がある。掲載ページを調べる価値がある

### ② GA4のセッション < ktrackgeo の訪問回数

主な原因は3つ。順に確かめてください。

1. **広告ブロッカー** — GA4 は外部ドメインを読むためブロックされます。
   ktrackgeo は自社ドメインなので残ります。**差の割合がそのままブロック率の目安**です。
2. **同意管理** — Cookie 同意を取っていない訪問は GA4 に入りません。
3. **ボットの扱い** — GA4 はボットを除外し、ktrackgeo は分けて数えます。
   比べるときは ktrackgeo 側の**人のPV**を使ってください（ボットを混ぜない）。

逆に **GA4のほうが多い**場合は、ktrackgeo のタグが一部のページに入っていないことを疑います。

### ③ ktrackgeo のAI件数が0

**まず設置方法を確認してください。**JSタグだけの場合、これは正常です。
クローラーは JavaScript を実行しないので、**タグ方式では原理的に拾えません。**

サーバー側計測（`require_once`）が入っているのに0なら、次を疑います。

- `robots.txt` でAIクローラーを拒否している → **GEO診断の robots を見る**
- そもそも見つけられていない → `llms.txt`・構造化データが無い

### ④ GEO診断は高得点なのに、AIが来ていない

**診断は「読める状態か」、実測は「実際に来たか」**です。両方見て初めて意味があります。

- 診断が高く実測が0 → **見つけられていない。**外部からの被リンク、sitemap、llms.txt を疑う
- 診断が低く実測もある → クローラーは来ているが引用されにくい。診断の指摘から直す
- 直したのに実測が増えない → クローラーの再訪には時間がかかる。2〜4週間おいて再確認

## データの集め方

### ktrackgeo

ログを直接読みます。1行 = `日時 | 訪問者ID | URL | 参照元 | UA | ページ名`。

```
access-YYYY-MM.log
```

画面（`?dashboard=1`）でも要約が見られます。`geo-history.json` に診断の点数の履歴があります。

### Search Console / GA4

**APIとCSVの2通りがあります。CSVで構いません。**

- **CSV** — 各画面の「エクスポート」から落としたファイルを読ませてもらう。
  権限設定が要らないので、こちらを既定にしてください。
- **API** — サービスアカウントを作り、GSC は「ユーザーと権限」、
  GA4 は「プロパティのアクセス管理」に**閲覧者**として追加する。
  GA4 は `analyticsdata.googleapis.com` の有効化も必要。

APIの設定は非エンジニアには重い作業です。**先にCSVで進め、必要になってから提案**してください。

## 報告の書き方

**数字の羅列にしないこと。**次の順で、日本語の文章にしてください。

1. **今どうなっているか** — 人のアクセス、AIの訪問、GEO診断の点。前期間との増減
2. **食い違いとその理由** — 上の①〜④のどれに当たるか。数字を挙げて説明する
3. **次に何をするか** — 3つまで。効果の大きい順。**やらなくていいことも言う**

### 言ってはいけないこと

- **断定できないことを断定しない。**「Google検索から」ではなく「Google経由で」
- **原因を1つに決めつけない。**GA4との差は複数の要因が重なる
- **「対応が必要です」と判断しない。**事実と選択肢を示し、決めるのは人
- **数字が少ないことを失敗と呼ばない。**期間・季節・母数を確認してから話す

## 検算

報告の前に必ず確かめてください。

- 期間は3つとも揃っているか（GSCは**2〜3日遅れ**る。同じ日付範囲でも欠ける）
- ktrackgeo 側で**人とボットを混ぜていないか**
- 参照元は**訪問の入口**だけを数えているか（ページを開くたびに数えると水増しになる）
